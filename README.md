# MarketPulse AI

MarketPulse AI is a transparent financial-market analytics dashboard for
exploring XAUUSD (Gold/USD) candles, technical indicators, model-generated
direction probabilities, explainability data, model performance, historical
analytics, and future data integrations.

It is designed as a college data-science demonstration project. It does **not**
promise future prices, execute trades, or provide financial advice.

## Current product surface

- `/` — dashboard overview with sample OHLCV candles, a candlestick-style
  price chart, latest prediction, model status, indicator visibility, and
  research disclaimer.
- `/prediction` — latest direction, confidence meter, horizon, model
  metadata, feature explanation state, and transparent unavailable states.
- `/chart-analysis` — upload a PNG/JPEG TradingView screenshot for a single
  local pixel scan, then combine the visible chart geometry with the loaded
  XAUUSD D1 model baseline. The result includes a model-anchored price band
  and bullish, sideways, and bearish scenarios. The image is not uploaded or
  persisted, and this path makes no external AI call.
- `/performance` — imported metrics, model comparison, confusion matrix, and
  training-data provenance. Values stay `Not available` until real metadata is
  supplied.
- `/analytics` — prediction accuracy, bullish/bearish distribution,
  calibration, and accuracy-over-time states.
- `/settings` — saved asset/timeframe preferences, CSV upload validation and
  preview, live-data placeholder, news-sentiment placeholder, and model
  integration guidance.

The asset selector is intentionally future-ready for `XAUUSD`, `EURUSD`,
`GBPUSD`, `USDJPY`, `EURJPY`, and `BTCUSD`; XAUUSD is the initial dataset.

## API contract

`lib/api-spec/openapi.yaml` is the only source of truth for API request and
response shapes. After changing it, regenerate the typed client and Zod
schemas before changing frontend or server code:

```bash
pnpm --filter @workspace/api-spec run codegen
```

Current MarketPulse endpoints:

- `GET /api/healthz`
- `GET /api/market-data?asset=XAUUSD&timeframe=1H&limit=72`
- `GET /api/indicators?asset=XAUUSD&timeframe=1H`
- `GET /api/prediction?asset=XAUUSD`
- `GET /api/model-info`
- `GET /api/feature-explanations`
- `GET /api/performance`
- `GET /api/analytics`
- `POST /api/chart-analysis` — accepts screenshot measurements produced by the
  browser scanner and returns visual bias, chart geometry, a model-calibrated
  price band, three weighted scenarios, agreement, and safety disclaimers. It
  intentionally does not accept or store image bytes.

Frontend hooks are generated by Orval and imported from
`@workspace/api-client-react`. Do not hand-write duplicate API types.

## Connecting the Google Colab model

Do not train the model in Replit. Train and export it from Google Colab, then
place the artifacts in `artifacts/api-server/model-data/`.

The directory contains a `README.md` with the supported metadata shape. At a
minimum, export:

1. the serialized model (`.pkl`, `.joblib`, or another format supported by the
   future inference service);
2. the preprocessing/scaler artifact;
3. a `metadata.json` containing the exact feature names and ordering;
4. model metrics and comparison results;
5. optional SHAP or feature-importance output.

The feature list is the contract between Colab and inference. The future
Python inference service must:

- load the model and preprocessing objects securely;
- engineer the same features from Open, High, Low, Close, and optional Volume;
- validate that every configured feature exists;
- order the feature vector exactly as `metadata.json` specifies;
- return a clear missing-feature/model-loading error rather than guessing;
- keep technical features and optional news sentiment as separate pipeline
  stages before combining them.

The current app safely runs in **sample mode**. When `metadata.json` is absent,
performance and explainability values are not invented. The current
direction/probability is explicitly labelled as a sample preview so the app
can be demonstrated before the real model is connected.

## CSV upload expectations

The Settings page accepts a local CSV for preview and validation. Required
columns are:

- `Open`
- `High`
- `Low`
- `Close`

`Volume` is optional. Column matching is case-insensitive and whitespace
tolerant. The UI reports missing columns and shows a preview without silently
submitting invalid data.

## TradingView screenshot analysis

The Chart reader page is a useful first integration for screenshot workflows,
but it is not computer vision OCR and it is not a live trading engine:

1. The browser decodes the selected PNG/JPEG locally.
2. It scans the central chart area for green/red pixels and estimates the
   left-to-right trajectory.
3. It sends only numeric measurements and short signal notes to
   `POST /api/chart-analysis`.
4. The API compares that visual bias with the existing loaded XAUUSD D1
   directional baseline and returns whether the two agree.

The current XGBoost metadata is real project metadata, but the serialized model
and scaler are not present in `artifacts/api-server/model-data/`. The server's
existing prediction function is therefore a calibrated baseline over the
available dataset, not a claim that a screenshot has been fed into the
trained model. For production-quality screenshot inference, add the real model
artifacts, OHLC extraction/OCR, timeframe detection, and an inference service
before describing the result as a live AI prediction.

Best screenshot inputs:

- crop to the TradingView chart area;
- keep candlesticks visible and avoid browser chrome/sidebar overlays;
- use PNG/JPEG under 10 MB;
- prefer a chart with clear green/bearish candle colors.

## Future implementation guidance for AI agents

Read this file and the uploaded product brief before making changes. Preserve
these boundaries:

- Keep the OpenAPI document, generated hooks, and Zod schemas in sync.
- Use the shared Express API server for app routing unless a dedicated Python
  inference service is explicitly added and wired through an artifact workflow.
- Do not add local authentication, JWTs, API keys, or hardcoded secrets.
- Do not invent metrics, SHAP values, test accuracy, or live market prices.
  Render unavailable states when source files do not provide those values.
- Keep screenshot visual analysis, model baseline, and loaded serialized-model
  inference clearly distinct.
- Keep model loading and feature engineering modular; never hardcode feature
  order in a route handler.
- Add new assets by extending the asset configuration rather than duplicating
  page logic.
- Use the generated `@workspace/api-client-react` hooks in the frontend.
- Use `req.log`/the shared Pino logger in server routes; never add
  `console.log` to backend code.
- Prefer small focused modules over a large page or route file.
- When adding persistent uploaded files, use App Storage for bytes and only
  keep object paths/metadata in PostgreSQL.

### Safe next steps

1. Replace the browser pixel scan with the existing Python chart-analysis
   service once its OCR/pattern pipeline is implemented and validated.
2. Add an OpenAPI-backed OHLC upload endpoint that receives validated candle
   data and returns a prediction from the serialized model.
3. Add a Python inference service that reads the serialized model, scaler,
   feature list, and metadata from `model-data/`.
4. Export prediction history from the inference pipeline so analytics and
   calibration use observed outcomes.
5. Export SHAP values and comparison metrics from Colab into metadata files.
6. Add a real market-data connector only after the user authorizes a provider.
7. Enable news sentiment as an optional feature block, never as a required
   dependency for the technical-only model.
